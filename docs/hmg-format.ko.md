# Eastward HMG 형식

[English](hmg-format.md) | 한국어

HMG는 `PGF` 헤더와 LZ4로 압축한 RGBA 픽셀 데이터로 구성됩니다. 헤더 길이는 패딩에 따라 달라집니다.

## 구조

정수는 리틀 엔디언으로 저장합니다. `A`와 `B`는 각각 오프셋 `3`, `22 + A`에 저장된 패딩 길이입니다. 표의 크기 단위는 바이트입니다.

| 오프셋 | 크기 | 필드 |
| --- | --- | --- |
| `0` | 3 | ASCII `PGF` (`50 47 46`) |
| `3` | 1 | 첫 패딩 길이 `A` |
| `4` | 4 | 전체 크기 `S` |
| `8` | `A` | 첫 패딩 |
| `8 + A` | 4 | 압축 길이 `C` |
| `12 + A` | 4 | 너비 `W` |
| `16 + A` | 4 | 높이 `H` |
| `20 + A` | 1 | 픽셀 폭 선언: 32 |
| `21 + A` | 1 | LZ4 가속도: 1 |
| `22 + A` | 1 | 두 번째 패딩 길이 `B` |
| `23 + A` | 1 | 대체 복사 플래그: 0 |
| `24 + A` | `B` | 두 번째 패딩 |
| `24 + A + B` | `C` | LZ4 raw block |

```text
payloadOffset = 24 + A + B
S             = payloadOffset + C
pixelBytes    = W * H * 4
```

전체 크기와 압축 길이는 부호 없는 32비트 정수, 너비와 높이는 부호 있는 32비트 정수입니다. 두 패딩 길이가 모두 0이면 압축 데이터는 오프셋 24에서 시작합니다.

## 픽셀과 압축

픽셀은 RGBA8888 형식으로, 압축 전 크기는 `W * H * 4`바이트입니다. 헤더의 값 32는 픽셀당 비트 수로 추정됩니다. 읽기 함수는 이 값을 사용하지 않으므로 24로 바꿔도 RGB888로 읽히지는 않습니다.

압축 데이터는 LZ4 raw block 형식입니다. LZ4 frame 헤더는 포함하지 않습니다. 가속도 값은 압축할 때만 사용하며 압축 해제에는 영향을 주지 않습니다.

## 패딩

게임의 생성 함수는 두 패딩 길이를 각각 `rand() % 4 + 1`로 정하고 난수 바이트로 채웁니다. 읽을 때는 길이만큼 건너뜁니다.

패딩을 바꾸거나 제거해도 길이와 전체 크기를 맞추면 픽셀 데이터는 달라지지 않습니다.

## 대체 복사 플래그

플래그가 0이면 이미지 버퍼에 직접 압축을 풉니다. 0이 아니면 `W * H + 1024`바이트의 임시 버퍼를 할당합니다. 이 분기는 소스를 네 바이트씩 읽으면서 쓰기 위치를 한 바이트씩 이동합니다. 쓰는 영역이 겹치고, 큰 이미지에서는 버퍼 범위를 넘어 읽을 수 있습니다.

게임의 생성 함수는 항상 0을 기록합니다. JS와 C# 라이브러리에서도 0인 경우만 지원합니다.
