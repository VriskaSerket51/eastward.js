# Eastward HMG 형식

[English](hmg-format.md) | 한국어

`PGF` 헤더와 LZ4로 압축한 RGBA 픽셀을 담습니다. 헤더 길이는 패딩에 따라 달라집니다.

## 구조

정수는 little-endian입니다. `A`는 오프셋 3, `B`는 오프셋 `22 + A`의 값입니다.

| 오프셋 | 크기 | 필드 |
| --- | --- | --- |
| `0` | 3 | ASCII `PGF` (`50 47 46`) |
| `3` | 1 | 첫 패딩 길이 `A` |
| `4` | 4 | 전체 크기 `S` |
| `8` | `A` | 첫 패딩 |
| `8 + A` | 4 | 압축 길이 `C` |
| `12 + A` | 4 | 너비 `W` |
| `16 + A` | 4 | 높이 `H` |
| `20 + A` | 1 | 픽셀 폭 선언: 32 |
| `21 + A` | 1 | LZ4 가속도: 1 |
| `22 + A` | 1 | 두 번째 패딩 길이 `B` |
| `23 + A` | 1 | 대체 복사 플래그: 0 |
| `24 + A` | `B` | 두 번째 패딩 |
| `24 + A + B` | `C` | LZ4 raw block |

```text
payloadOffset = 24 + A + B
S             = payloadOffset + C
pixelBytes    = W * H * 4
```

크기는 32비트 unsigned, 치수는 32비트 signed입니다. 패딩이 모두 0일 때 데이터가 오프셋 24에서 시작합니다.

## 픽셀과 압축

픽셀은 RGBA8888이며 압축 함수에 `W * H * 4`바이트를 전달합니다. 선언 32는 픽셀당 비트 수로 추정하지만 읽기 함수는 이 필드를 사용하지 않습니다. 24로 바꿔도 RGB888이 되지 않습니다.

데이터는 LZ4 frame이 아닌 raw block입니다. 가속도는 압축 탐색에 사용하며 해제에는 사용하지 않습니다.

## 패딩

생성 함수는 두 패딩 길이를 `rand() % 4 + 1`로 정하고 난수 바이트를 채웁니다. 읽기 함수는 건너뜁니다.

패딩을 바꾸거나 크기를 맞춰 제거해도 픽셀은 같습니다.

## 대체 복사 플래그

0이면 이미지 버퍼에 직접 해제합니다. 다른 값의 분기는 임시 버퍼를 `W * H + 1024`바이트 할당하고 소스를 네 바이트씩 읽으면서 목적지를 한 바이트씩 이동합니다. 쓰기가 겹치며 큰 이미지에서는 범위를 넘는 읽기가 발생할 수 있습니다.

생성 함수는 0을 기록합니다. JS/C# 구현은 0이 아닌 플래그를 거절합니다.

## 구현

JS는 `readHMGHeader`, `decodeHMG`, `encodeHMG`, C#은 `HmgHeader`와 `HmgAsset.Header`를 사용합니다. 읽은 패딩을 보존하거나 빈 패딩을 지정할 수 있습니다.

패딩 길이에 따라 헤더 크기를 계산해야 합니다. 압축 해제 결과는 `W * H * 4`바이트여야 합니다. 아틀라스 alpha 변환은 텍스처 계층에서 처리합니다.
